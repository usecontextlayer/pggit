## Notes

- **Counts:** 11 assigned → 11 converted. Nothing dropped, nothing split, no source script touched. No wire script is a utility or a shared helper — all 11 are tests/harnesses.
- **Expected-state column is a reading of the sources, not a run.** Per the conversion spec I did not run vitest, `tsc`, biome, or touch Postgres. `wire--delta-before-base-ordering` is marked RED because its own header records the measurement that makes it red (100% of served REF_DELTAs ahead of their base vs canonical git's 0%). The other nine e2e sources carry no recorded reproduction in their headers — only the standard `exit 0 = correct` contract — so they are marked GREEN negative; any of them turning red is a real finding, not a conversion artifact.
- **Fixture scale is preserved exactly:** 300 (+12) runs for ordering; 200 runs × 400 branches for exact-oid/gzip; 20+90 commits for force-push; 140 (+60) runs for incremental fetch; 90 commits × 2 scenarios × 8 checkpoints for repack passes; 1200 (+40) runs and 250 divergent client commits for large trees; 90 steps for the orphan shared tree; 120 runs for blobless; 8 shapes × 110 commits for the fuzz. Probabilistic loops keep their pinned seeds and iteration counts.
- **The real-git oracle is preserved everywhere the source had one:** a plain bare `file://` remote runs the identical sequence in `exact-oid-and-gzip`, `incremental-fetch-deltified`, `large-trees-and-negotiation`, `partial-clone-blobless`, `shape-fuzz-differential` and the perf harness, and `git fsck --strict --no-dangling` / `git verify-pack -v` judge every clone.
- **Failure collection → assertions:** each source accumulated failures and exited 1 at the end. The e2e conversions drive the whole sequence in `beforeAll` (recording each arm's error and observation) and assert over the recorded results in `it` blocks, so one broken arm still reports every other arm — the same "record and keep going" shape, expressed as tests.
- **Postgres:** every e2e test takes `createIsolatedSchema(inject("pgBaseUrl"))` and `drop()`s it in `afterAll`; no `:6489` literal survives in `src/`. The perf harness keeps the standalone-tsx convention with `--pg=` defaulting to `postgres://postgres:postgres@localhost:6489/postgres`.
- **`wire--shape-fuzz-differential` uses one isolated schema for all 8 shapes** (the source carved a fresh schema per shape). Each shape still pushes to its own repo name `workspace/fuzz/s<seed>`, and repack/GC/serve are all per-`repo_id`, so the shapes remain mutually invisible — this changes only setup cost, not what is tested.
- **`wire--pack-shape-vs-git` is the one perf routing call.** Two of its four exit conditions are byte thresholds (repacked clone/fetch larger than un-repacked), it reports size ratios it deliberately does not assert, and it already carried `--runs=`/`--new=` flags — the perf-harness signature. Its correctness sub-checks (max chain depth ≤ 1 on both the clone and the incremental fetch, fsck on all three clones, three-way object-set agreement) are kept inside that single destination rather than split into a second file.
