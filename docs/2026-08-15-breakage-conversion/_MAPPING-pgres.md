## Conversion notes

- **Shared-instance caveats preserved verbatim** in every destination header: instance-wide counters (`pg_current_wal_lsn()`, `pg_stat_sys_tables`, the xmin horizon) are polluted by sibling agents, so ratios and paired/interleaved arms are the findings, never absolute bytes; and this Postgres runs `full_page_writes=off` / `fsync=off`, which suppresses full-page-image WAL — every WAL number is a LOWER BOUND on a production instance.
- **Perf shape**: each harness is standalone tsx with a `main()` ending in `.catch((err) => { console.error(err); process.exitCode = 1 })`, prints its measurement tables, and sets `process.exitCode = 1` past its stated bound (replacing the source's `process.exit(...)`).
- **Routing exception, decided here**: `pgres--encoding-storage-profile.ts` is the one script routed to e2e. Its verdicts are discrete catalog facts (a storage class, a reloptions set, whether the out-of-line payload was compressed) over a hermetically built fixture; the byte numbers are evidence for those facts, not a cost threshold. Its source `bigBytes > 1_000_000` FAIL gate became a fixture precondition so the placement assertion is unconditional, and the reloptions drift — which the source REPORTED rather than bounded — became an assertion of the parity 0008's own comment claims, which is where the known RED finding (`autovacuum_vacuum_cost_delay=0`) lives.
- **`pgres--pool-starvation.ts` stayed one artifact** despite carrying a correctness property (no clone fails, final clone fsck-clean and complete): its PRIMARY verdict is the p95 latency ratio, so it routes perf and keeps the correctness sub-check inside.
