# Mapping — `realrepo` lens: `breakage/` repro scripts → house testing patterns

6 source scripts assigned, 6 converted. Every one routed to **perf** (`perf/breakage/`): each drives a REAL local repository handed in at run time, which is the routing rule's second trigger ("the script needs a real EXTERNAL repo"), and three of them additionally score a MEASURED size ratio. None can become a vitest e2e test, because there is no committed fixture that can stand in for the corpus — the same reason `perf/delta-corpus.ts` and `perf/delta-probe.ts` live in `perf/`.

| source (`breakage/…`) | destination | kind | exact property it asserts / measures | expected current state |
|---|---|---|---|---|
| `realrepo--branch-order.ts` | `perf/breakage/realrepo--branch-order.ts` | perf | Pushes every ref of a real repo ONE AT A TIME with a `repack()` between each push, in forward AND reverse order (D4: anchors freeze over a partial DAG, a later branch introduces new same-path pairs). Per order: push accept/reject parity with a `file://` oracle receiving the identical per-ref sequence, `git fsck --strict` clean, object set + ref listing byte-identical to the oracle, and `git verify-pack -v` chain depth ≤ `--max-depth` (default 1, the D2/D9 structural bound) as the CLIENT measures it. Cross-order: the two orders must serve identical object sets. Exit 1 on any finding. | perf-diagnostic (correctness gate on real history; the source's own verdict line claims exit 0 = clean, so any finding here is new) |

Everything unattributable is left alone (the instance is shared with other sessions). | n/a — teardown for runs that died before their own `finally` |
| `realrepo--differential.ts` | `perf/breakage/realrepo--differential.ts` | perf | Wire-level differential on a real repo against a `file://` bare oracle replaying the identical push. **full**: push `--mirror` (fallback `--all --tags`), pre-repack clone ≡ oracle (D1: encoding is derived), `repack()` then a second pass MUST write 0 rows (D4 frozen policy), post-repack mirror clone compared object-for-object by SHA-256 over `<type> <size>\0<content>`, ref-for-ref, and `git fsck --strict`. **size**: served pack bytes vs `git gc --aggressive` over the same object set — a finding past 4.0x. **shapes**: single-branch clone, tag-only fetch, `--filter=blob:none` clone + lazy promisor blob backfill (bytes must match git's), exact-OID fetch of 3 historical commits, shallow clone must fail LOUDLY (no 500, no silent success, cause named), then `gc(graceSeconds: 0)` + re-clone and `repack` + re-clone still ≡ oracle (D7 hygiene). **orphan** (opt-in via `--phases=orphan`): a denied non-FF push must be REJECTED while its objects land, must never leak into a served pack, `gc` must reclaim them (0 reclaimed is a finding), and clone ≡ oracle before/after gc/after repair repack. **replay**: every `--step`th first-parent commit pushed in sequence with the repack SKIPPED every 3rd round, incremental fetch each round, tip correct, `fsck --strict` clean, full object-set compare every 4th round and at the end, plus a FRESH clone of the replayed repo ≡ oracle. Exit 1 on any finding. | perf-diagnostic (correctness gate across 4–5 phases + one measured ratio, both feeding the single exit code, exactly as the source did) |
| `realrepo--drain-races.ts` | `perf/breakage/realrepo--drain-races.ts` | perf | The four conditions the production drain (W1) will create, each verified by a clone compared against a `file://` oracle that received the identical push: **R1** two clones of one unchanged repacked state must be byte-identical packfiles (sha256 over the received packs — `buildPack` documents deterministic packs), **R2** a clone racing an in-flight `repack()` must still produce a valid, oracle-identical pack (serve reads encodings per 1000-object batch, so the racing clone necessarily sees a half-encoded repo), **R3** a push landing mid-repack must succeed and the converged state must clone ≡ oracle, **R4** two overlapping `repack()` calls on ONE repo — a loud throw is acceptable, a corrupt or short pack is not; after one more repack the clone must still be fsck-clean and oracle-identical. | `realrepo--incremental-fetch-size.ts` | `perf/breakage/realrepo--incremental-fetch-size.ts` | perf | The WARM path nothing measured: replays a real repo checkpoint by checkpoint (`--step`, default 50), repacking pggit and `git gc`-ing the `file://` oracle each round, then measures the pack actually transferred for each incremental fetch on both sides (`fetch.unpackLimit=1` keeps the received pack on disk, so the on-disk delta IS the wire bytes). Verdict: total pggit/git ratio vs `--max-ratio` (default 3.0, the design's measured ~2.4x parity plus headroom). | RED / reproduced — the tier deltifies TREES only (repack phase 1 walks tree lineages, phase 2 sweeps everything else whole); on an ordinary source repo the rewritten large text blobs are where git wins and pggit pays full deflate per version |

## Conversion notes

- **Mirror-clone-before-touch is now enforced in one place.** Every harness resolves its corpus through `prepareMirror`, which does `git clone --mirror --no-hardlinks -q <source> <scratch>/source.git` (the discipline `perf/delta-corpus.ts` documents) and hands back the private clone. The harnesses push from it, `git config uploadpack.*` into it (the differential), and `git gc` the oracles built out of it, so the source checkout — `pggit`, `trove`, `web`, a customer mirror — stays byte-for-byte pristine. The sources took a pre-made `--mirror=<bare.git>` and worked on it directly; both spellings are accepted (`--repo=` preferred, `--mirror=` still honoured), and both now go through the clone.
- **Nothing else about what these scripts test changed.** Every check, threshold, `--flag` name and default, oracle comparison, printed table and exit code is carried over verbatim; the `file://` real-git oracle and the `verify-pack`/`fsck` inspections are untouched. The only substitutions are mechanical: the local `flag`/`mk`/`tryGit`/`fail`/`oidSet`/`packBytes` copies now come from `_realrepo-util.ts`, `Awaited<ReturnType<typeof createIsolatedSchema>>` is spelled `IsolatedDb`, and `realrepo--cleanup.ts`'s top-level body is wrapped in the house `main().catch(…)` shape with the hard-coded DSN moved behind the same `--pg=` flag (same default).
- **Repo-id prefixes are load-bearing** and unchanged: `border/…` (branch-order), `races/…` (drain-races), `realrepo/…` (differential), `warm/…` (incremental-fetch-size), `sizecheck/…` (serve-size-vs-git). `realrepo--cleanup.ts` attributes schemas by exactly these prefixes; renaming one silently orphans its schemas on the shared Postgres.
- **No source file was modified** and nothing outside `perf/breakage/` was created.
