# Breakage conversion mapping — lens `lifecycle`

11 source scripts assigned, 11 converted. Every one routed to **e2e**: each verdict is a correctness property (clone/fetch success, `git fsck --strict`, object/ref-set and byte-for-byte identity against a `file://` oracle, repack convergence, or a specific throw), and each builds its own repo hermetically via `git fast-import`. No script in this lens measures a threshold or needs an external repo, so `perf/breakage/` holds only this mapping.

## Basis for the RED/GREEN column

Two scripts declare themselves `FINDING —` in their header, state an explicit `Exit 0 = bug gone / Exit 1 = reproduced` verdict, and are **self-contained** (no `_lib.ts` import) — which is exactly the discipline `_lib.ts` documents: *"EXPLORATORY ONLY — each confirmed finding ships as a self-contained `lifecycle--<slug>.ts`."* Those two are expected RED. The other nine import `_lib.ts`, are headed `Exploration N —` / `Lifecycle probe —`, and end in the generic `failures === 0 ? "OK" : "FAILURES"` — explorations retained as regression probes, expected GREEN. This is inference from the scripts themselves; nothing was executed during the conversion (the spec forbids running vitest/tsc/biome or touching Postgres), so the column is a prediction, not an observation.

## Conversion notes

- Assertions encode the CORRECT outcome, never the source's exit-1 condition — so a live reproduction shows up RED.
- Every scenario runs once in `beforeAll` (they are strictly sequential state machines) and records a typed observation per round/step; the `it` blocks then pin one property each and fail with the full list of offending rounds. Nothing reaches inside the store — the observables are the git wire surface, the `file://` oracle, and the public `repack()`/`gc()` return values.
- Fixture scale, round counts, branch points, grace windows, gc/repack orderings and the fuzz seed are all preserved verbatim. `--seed=` / `--rounds=` argv reads became pinned constants (seed 1, 40 rounds), matching how the generative differentials pin their fast-check seeds for a deterministic gate.
- Hook timeouts are explicit (600s–1800s) because vitest's default `hookTimeout` is 10s and the config's `testTimeout: 600_000` does not cover hooks.
- One behavioural detail deliberately preserved in `lifecycle--repo-recreate-cycles`: on a clone failure the source `continue`s WITHOUT deleting the repo, so the next cycle runs against the same incarnation.
