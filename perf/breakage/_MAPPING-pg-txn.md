# Breakage conversion mapping — lens `pg-txn`

8 source scripts assigned, 8 converted. Every one is a fault-injection **correctness** repro (its verdict is a clone/push/invariant/convergence property, and it builds its own repo hermetically via `createAppendOnlyRepo` or an inline `git fast-import`), so all 8 route to **e2e** under `src/e2e/breakage/`. None routes to `perf/breakage/` — no script's primary verdict is a measured threshold, and none mirror-clones an external repo.

Every test sources Postgres from `createIsolatedSchema(inject("pgBaseUrl"))` and builds its own extra pools with `postgres(baseUrl, { connection: { search_path: db.schema, … } })`; `:6489` appears nowhere. Fault-injection mechanics are preserved verbatim (`statement_timeout` connection params, `pg_cancel_backend`, `pg_terminate_backend`, `lock table … in access exclusive mode`, `select … for update`), and every `pg_terminate_backend` / `pg_cancel_backend` targets only a pid the test itself read from a connection it opened.

## Notes

- **Helpers.** None of the 8 assigned scripts imports a `breakage/_*.ts` helper (verified by reading every import line). The exploratory probes `_probe.ts`, `_txn-probe.ts`, `_copy-hang-probe.ts` and `_gc-timeout-probe.ts` are standalone one-shot probes with no importer — **utility/helper, not a test**, and not in this lens's assignment. Each script's own local helpers (`tryGit`, `gitBounded`, `lsTree`, `invariant`, `counts`, `liveClosure`, the fast-import `history()` builder) are inlined into their destination test, per the house e2e style.
- **Fixture scale is unchanged.** 1200 / 700 / 600 / 700 / 3000-dir / 900 runs, 12 race iterations, 11 fault points, 4 cancel points, 2 CAS points, 4 attempts, 4 modes × 4 children — every count is the source's.
- **`pg-txn--txn-death-kills-host-process` needs a child process, and that is load-bearing.** The crash fires from a `setImmediate`, so no `try/catch`, `.catch()`, or vitest hook in the test process could ever observe it — only an exit code can. The child program is emitted at run time to `perf/breakage/_pg-txn-death-child-<uuid>.ts` (deliberately outside `tsconfig.json`'s `include: ["src/**/*.ts"]`, so even a stray copy can never break `tsc`) and removed in `afterAll`. It is spawned with `npx tsx` from the repo root, and it reads the base URL and schema from `BK_PG` / `BK_SCHEMA`.
- **Two deliberate tightenings, both teardown/observation only, neither changing what is asserted.** (1) `pg-txn--gc-poisons-pooled-connection` tags its shared pool with an `application_name` and filters `pg_stat_activity` on it — the source script had a Postgres container to itself, while the globalSetup container here is shared with every other test file. (2) `pg-txn--copy-cancel-hangs-push-forever` terminates its own stranded backend pid in `afterAll` before `db.drop()`, because that connection's locks would otherwise block `drop schema cascade` forever and leak a schema on the shared container.
- **Diagnostics the source printed but never failed on are preserved as prose, not as assertions** — e.g. the ingest sweep's note that objects can commit while `repos.last_pushed_at` stays NULL (invisible to the GC drain until a later push stamps the repo), and the copy-cancel finding that no rows land so the store stays consistent. Asserting either would invent a check the source did not make.
